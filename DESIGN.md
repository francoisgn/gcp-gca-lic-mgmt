## 1. Principles

1. **One thing per screen.** The landing page answers one question — *"what is the state of my license?"* — before anything else.
2. **Progressive disclosure.** Forms reveal one question at a time; each answer unlocks the next one. Nothing is shown before it is useful.
3. **Status is always explicit.** Every state uses the RAG vocabulary (§3.3) in the same way across pages: left progress panel, badges, alerts, KPI tiles.
4. **Accent with restraint.** Two gradients, two roles: the **Gemini gradient** is the *brand* (top bar logo and `> GCA` wordmark only); the **accent gradient** (faded teal → green → lime) carries every other accent (primary action, active step, selection, key numbers, charts). Faded, never neon: no saturated pink or violet on the dark background. Never as a background of large surfaces.
5. **Negative space over borders.** Separate with spacing first, then with a 1 px low-contrast border, never with heavy lines.
6. **Calm motion.** Animations explain a change (reveal, loading); they never decorate. `prefers-reduced-motion` disables them.

**Gemini gradient (brand only)** — `--gradient-gemini`: `#4796E4 → #847ACE → #C3677F` (90°). Used by the top bar logo / wordmark and the `> GCA` ASCII wordmark, nowhere else.

**Accent gradient** — `--gradient-accent`: `--acc-teal #4fa596 → --acc-green #7dbb86 → --acc-lime #bfd38a` (90°, green at 55 %), diagonal variant `--gradient-accent-diag` (135°). Desaturated on purpose: calm on the dark background. Dark text on it keeps a contrast ≥ 6:1 on every stop.

### 3.2 Semantic colours

| Token | Value | Role |
|---|---|---|
| `--bg` | crust | Page background (with two faint radial glows, teal top-left, lime top-right) |
| `--bg-elevated` | base | Dialogs, toasts, sticky bars |
| `--surface` | mantle | Inputs, tiles, table headers |
| `--surface-2` / `--surface-3` | surface0 / surface1 | Chips, secondary buttons, hover |
| `--border` / `--border-strong` | text @ 8 % / 16 % | Hairlines |
| `--text` / `--text-muted` / `--text-faint` | text / subtext0 / overlay1 | Three levels only |
| `--link` | mint `#8fcfba` | Links |
| `--accent` | mint `#8fcfba` | Checked states, accent badges; focus ring and focused inputs use `--acc-teal` |

### 3.3 Status (RAG)

| State | Token | Colour | Used for |
|---|---|---|---|
| 🟢 OK | `--ok` | green `#a6e3a1` | Step done, active license, healthy KPI |
| 🟠 Warning | `--warn` | peach `#fab387` | Buffer (timeout), close to a limit, unused license |
| 🔴 Critical | `--ko` | soft red `#e78284` (Catppuccin Frappé red — less pink than Mocha red) | Pool exhausted, rejection, failure, deviation |
| 🔵 Info | `--info` | blue `#89b4fa` | Waiting list, pending admin decision |
| ⚪ Idle | `--idle` | overlay0 | Not started / not applicable (e.g. admin validation not needed) |

Tinted surfaces use the status colour at 8–14 % opacity with a 45–60 % border (e.g. the *Pool exhausted* box: red border on faded red background).

### 3.4 Typography

| Role | Family | Weights | Token |
|---|---|---|---|
| UI (labels, buttons, tables) | **Roboto** | 400 / 500 / 700 | `--font-ui` |
| Long text (paragraphs, textareas) | **Open Sans** | 400 / 600 | `--font-text` |
| Display (titles, KPI values, step titles) | **Lato** | 700 / 900 | `--font-display` |
| Code, e-mails, IDs | Roboto Mono | 400 / 500 | `--font-mono` |

Scale: `12 · 13 · 15 (base) · 18 · 24 · 32 · 44` px (`--fs-xs` … `--fs-3xl`). Eyebrows: 12 px, uppercase, `letter-spacing: .12em`, muted. Sentence case everywhere (no Title Case except product names).

### 3.5 Spacing, shape, depth, motion

- **Spacing**: 4 px grid — `--s-1` (4) … `--s-16` (64). Cards: 24 × 32 px padding (20 px on mobile). Sections: 48 px apart.
- **Radius**: `--r-sm` 8 · `--r-md` 12 (inputs, tiles) · `--r-lg` 20 (cards) · `--r-xl` 28 · `--r-pill` (buttons, chips, badges).
- **Depth**: flat by default; `--shadow-1` on cards, `--shadow-2` on overlays. The primary button has a soft teal glow (18 % opacity).
- **Motion**: `--t-fast` 120 ms (press), `--t-med` 240 ms (hover, state), `--t-slow` 480 ms (reveal, progress). Easing `cubic-bezier(.2,.8,.2,1)`.

```
│  Your Gemini Code Assist license, self-service.                           │
├───────────────┬──────────────────────────────────────────────────────────┤
│ PROGRESS      │  Subscription status card / progressive form             │
│ ✓ Identity    │                                                          │
│ ✓ Training    │                                                          │
│ ④ Duration    │                                                          │
│ …             │                                                          │
└───────────────┴──────────────────────────────────────────────────────────┘
   300 px              fluid (max container 1280 px)
```

- Container: max 1280 px, 32 px gutters (16 px under 720 px).
- Landing: progress panel (left, sticky) + main frame. Under 960 px the panel becomes a horizontally scrollable strip above the frame.
- Admin pages: page header (eyebrow + H1 + one-line description), KPI tiles row, then tabs or sections.
- No horizontal page scroll at any width ≥ 360 px (tables scroll inside `.table-wrap`).

## 5. Components

| Component | Class | Rules |
|---|---|---|
| Top bar | `.topbar` | Sticky, 64 px, crust @ 72 % + 14 px backdrop blur. Navigation pills; active = surface-2 + inner hairline. |
| Pool counter | `.pool` | Pill with a 72 px gradient bar and `assigned / total` in mono. ≥ 90 % → orange→red bar; full → red border and bar; unknown → grey. Visible to everyone. |
| Card | `.card` | Mantle→base vertical gradient, 1 px border, `--r-lg`. `.card--accent` adds a gradient hairline border (main card of a page only). |
| Status line | `.status-hero` | 14 px glowing dot (RAG) + H2 + one muted sentence. First element of the subscription card. |
| Facts | `.facts > .fact` | Auto-fit tiles (min 170 px): uppercase label, value 18 px, muted relative date below. |
| Progress panel | `.steps > .step--{todo,active,ok,warn,ko,skipped}` | 28 px circle + label + hint. Active step: dark circle with a teal ring and soft glow. Connector turns green below completed steps. Skipped (admin validation not needed): 45 % opacity, italic. |
| Alert | `.alert--{ok,warn,ko,info}` | Icon + bold title + text. Used for the RAG messages (pool exhausted, buffer, rejection…). |
| Badge | `.badge--{ok,warn,ko,info,accent,plain,count}` | Pill with a 7 px dot. `--count` = solid red number (top bar). |
| Buttons | `.btn--{primary,secondary,ghost,danger,ok,sm}` | Pill, 42 px (32 px small). **One primary per view**: accent gradient with dark text (contrast ≥ 6:1 on every stop). Destructive actions use `--danger` and a confirmation dialog. |
| Chips | `.chip` (`aria-pressed`) | Radio-like choices and filter chips. Selected = gradient hairline border + check mark. |
| Progressive form | `fieldset.qa` | Accent-gradient **number badge, same numbers as the progress panel** (1 … 6; the final section covering credentials, license and e-mail shows *7–9*; width grows with the content, min 28 px) + title. Sections appear with `reveal` (8 px rise, 480 ms). Done = green tinted outline, failed = red tinted outline. Answers are frozen (`.form-readonly`) once sent to the directory. |
| Loader | `.loader` | Conic accent-gradient ring, rotating step message, 10 s progress bar (= UX timeout). |
| Position | `.position` | Huge accent-gradient number (`#3 of 12`) for queue and buffer positions. |
| Tables | `.table-wrap > table` | Uppercase 12 px headers, 11/14 px cells, hover row, secondary info in `.sub` muted line. |
| Tabs | `.tab[aria-selected]` | Text tabs with an accent-gradient underline. |
| KPI tile | `.kpi--{ok,warn,ko}` | Uppercase label, Lato 900 30 px value coloured by status. |
| Dialog / toast | `dialog`, `.toast--{ok,warn,ko}` | Native `<dialog>`; toasts bottom-right, coloured left border. `.dialog-pre` shows preformatted text (e-mail preview): mono 12 px on surface, scrolls beyond 60 vh. |
| Split layout | `.split`, `.split--aside` | Two cards side by side, one column under 860 px. `--aside` = 2 : 3 (form on the left, table on the right). |
| Directory check badge | `.badge--{ok,warn,ko,plain}` | Inventory *Directory* column: *ok* (green), *changed* / *check failed* (orange), *not eligible* (red), *not checked* (plain). Details in the tooltip. External accounts: `.badge--accent` *external* under the e-mail. |

## 6. Data visualisation

- Library: Chart.js 4 (vendored, no CDN at runtime).
- Axis text `subtext0`, grid lines text @ 6 %, no vertical grid lines, legend with 10 px point markers.
- Fixed series colours (never reassign them):

| Series | Colour |
|---|---|
| Auto assignment | green |
| Admin assignment | teal |
| Other assignment (back-port) | lavender |
| Removed — unused | peach |
| Removed — expired | yellow |
| Removed — admin | red |
| Removed — other | brick `#c98a7d` |
| Free seats | accent lime (dashed line, 22 % bar in the waterfall) · Start / End totals: overlay2 |
| Queue | blue · Buffer: peach · Deviations: red |
| Errors: TIMEOUT peach · 5XX red · 4XX brick · NETWORK yellow · RATE_LIMITED mauve · ERROR sand `#d9c4b8` · NOT_FOUND overlay |
| Latency p50 accent teal (solid) · p95 accent lime (dashed) |
| Page views accent lime (area) · Google license checks accent teal (dashed) |

- Removals are drawn **below zero** in the daily flow chart so that + and − read at a glance; the period waterfall uses floating bars (start → + → − → end → free seats).

## 7. Content & accessibility

- English only, short sentences, second person ("Your license is active").
- Dates: `02 Jan 2006`, with time `02 Jan 2006, 15:04`, in the configured time zone; always paired with a relative hint ("in 6 days").
- Colour is never the only carrier of meaning: every status also has an icon or a word.
- Contrast: body text ≥ 7:1 on `--bg`; muted text ≥ 4.5:1; primary button text (crust) ≥ 4.5:1 on every gradient stop.
- Focus: 3 px teal ring (`--ring`, `--acc-teal` @ 35 %) on every interactive element. Full keyboard navigation; dialogs trap focus natively.
- `prefers-reduced-motion: reduce` removes animations and transitions.
- No inline `<script>`; page data travels in `<script type="application/json">` (strict CSP).

## 8. Do / don't

| ✅ Do | ❌ Don't |
|---|---|
| Use the accent gradient on one primary action per view; keep the Gemini gradient for the brand | Fill large surfaces with the gradient |
| Use RAG tokens for any state | Introduce new status colours |
| Explain the next step in the alert text | Show raw error codes to users (keep them for admins) |
| Keep cards on a single column of content | Nest cards inside cards |
| Add the change to the changelog below | Change a token silently |
